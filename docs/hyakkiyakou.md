# OAS 百鬼夜行 AI 智能撒豆系统技术文档

本指南详细剖析了 OnmyojiAutoScript (OAS) 项目中，最具有视觉技术含量的模块——**百鬼夜行自动撒豆与智能鬼王选择系统**（`tasks/Hyakkiyakou`）。该系统深度集成了外置计算机视觉库 `oashya`，利用目标检测与多目标跟踪技术（ONNX 部署），实现了全自动、高精度的游戏操作。

---

## 1. 核心视觉架构与算法依赖

百鬼夜行系统摆脱了传统脚本死板的区域盲点连按，而是通过以下技术实现全画面式神动态追踪：

* **核心视觉组件**：**`oashya.tracker.Tracker`**。这是专门针对阴阳师百鬼夜行人物角色训练的高性能跟踪器。
* **推理引擎**：基于 **ONNXRuntime** 进行神经网络推理，执行 **FP32** 精度的实时目标检测与边界框 (Bounding Box) 估计。
* **配置参数控制**：
  - `conf_threshold`（置信度阈值）：控制识别门槛，滤除背景噪音。
  - `iou_threshold`（NMS 重叠阈值）：用于去除重叠的冗余检测框。
* **智能策略决策器**：**`tasks/Hyakkiyakou/agent/agent.Agent`**。负责根据识别到的式神稀有度、移动轨迹及剩余豆子数，实时输出射击指令（点击坐标 $x, y$、是否投掷 `throw`、撒豆数量 `bean`）。

---

## 2. 核心技术流详解

### 2.1 智能鬼王选择 (`_select_best_boss`)
在百鬼夜行开局前，界面会提供 3 个可选式神，被选中的式神将获得“鬼王加成”（豆子砸中奖励翻倍）。传统脚本只能随机挑选或固定选第一个，而 OAS 采用了完全自动化的**最佳鬼王识别与打分算法**：

```
进入鬼王选择界面 (I_HTITLE)
  ├── 遍历三个候选按钮 (C_HSELECT_1 至 3)
  │     ├── 点击当前按钮 -> 等待 1 秒界面稳定
  │     ├── 调用 _detect_current_rarity() 进行截图
  │     ├── 运行神经网络检测，根据式神类型输出稀有度评分
  │     └── 记录并累加评分 (scores.append)
  └── 挑选出评分最高（最佳稀有度）的候选按钮，进行最终确认锁定
```

#### 稀有度评分规则 (`_rarity_score`):
脚本为不同品质的式神建立了清晰的优先级梯度打分体系，以保证极品式神绝对被选为鬼王：
* **SP 品质** $\rightarrow$ **5分** (最高优先级)
* **SSR 品质** $\rightarrow$ **4分**
* **SR 品质** $\rightarrow$ **3分**
* **R 品质**（自动过滤无太大价值的童男、童女） $\rightarrow$ **2分**
* **N 品质** $\rightarrow$ **1分**
* **G 品质（呱太）** $\rightarrow$ **0分**
* 未检测到或不可识别的元素 $\rightarrow$ **-1分**

---

### 2.2 高频实时撒豆战斗循环 (`one`)
进入百鬼战斗场景后，游戏画面处于极速横向滚动状态。脚本的核心战斗控制机制由以下闭环支撑：

1. **多线程/高速截屏系统 (`fast_screenshot`)**：
   通过定制的高频截屏技术以极低延时获取屏幕缓冲区像素。
2. **多目标轨迹追踪推理 (`Tracker`)**：
   ```python
   tracks = self.tracker(image=self.device.image, response=last_action)
   ```
   每一帧图片都会喂入追踪器，追踪器返回当前画面中所有式神的 `(ID, RarityClass, Confidence, CenterX, CenterY, Width, Height)` 列表。
3. **AI 战术决策 (`Agent.decision`)**：
   根据追踪器提供的位置和用户配置的权重（针对 SP/SSR/SR 的撒豆权重，以及特定的目标黑/白名单 `priorities`），计算最优弹道交点。
4. **底层高频输入模拟 (`do_action` -> `fast_click`)**：
   避开了常规的 UI 延时模拟，利用 `fast_click(x, y)` 快速模拟多点触控向目标投掷豆子，在弹指间消耗豆子击中式神。

## 3. 调试与持续学习系统 (Debugger & Continuous Learning)

OAS 百鬼夜行系统设计了极为完善的开发者辅助调试模块：
* **实时框选渲染 (`hya_show`)**：可在副屏幕同步渲染绘制了检测框、式神名称、置信度和运动轨迹线条的实时监控画面（`draw_tracks`）。
* **持续学习采样器 (`continuous_learning`)**：如果开启，脚本会在撒豆执行过程中自动截取特定的识别偏差样本帧并本地保存，用于开发者后续重新标注和训练迭代 `oashya` 识别模型。
* **已知局限**：
  > [!IMPORTANT]
  > **冰冻状态 (Freeze) 的降级处理**：
  > 当界面触发“冻结 (Freeze)”全屏缓速特效时，由于全屏附着淡蓝色冰晶滤镜，且目标动作变形，目标识别率会严重下降（例如极其容易将所有被冻结角色误判为“蝉冰雪女”）。
  > 现行版本在检测到 `I_HFREEZE`（冻结标志）时，会主动跳过追踪推理 (`tracks = []`) 进行避错。
